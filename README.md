# Forte Vision

Локальный сервис для первичного просмотра видео кассовых операций. Он принимает `.mov`, асинхронно анализирует его и возвращает таймкод, JPEG-кадр и краткое описание события. Результат является сигналом для ручной проверки, а не юридическим или дисциплинарным выводом.

## Что входит

- Веб-интерфейс на русском языке.
- `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` с обязательным `X-API-Key`.
- Фоновая очередь с сохранением статуса в SQLite, ограничение размера файла, таймкоды и кадры в base64. Загруженное видео удаляется сразу после завершения обработки.
- Локальный обучаемый детектор визуальных событий. Обучение использует бинарные метки и таймкоды из предоставленного `open_labels.xlsx`; тип нарушения в исходной разметке не дан.
- Необязательное описание события через локальный Ollama с мультимодальной моделью. URL облачного сервиса запрещён проверкой loopback адреса.
- Автоматическое подавление повторных срабатываний ближе 4 секунд.

## Запуск на Windows через Docker Desktop

1. Установите Docker Desktop и распакуйте `open.zip` в отдельную папку. Для обучения нужна структура `open/open_labels.xlsx` и `open/videos/*.mov`.
2. В PowerShell из папки проекта создайте секрет и `.env`:

   ```powershell
   Copy-Item .env.example .env
   $key = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
   (Get-Content .env -Raw).Replace('replace-with-a-long-random-secret', $key) | Set-Content .env -NoNewline
   ```

3. Обучите модель на открытом датасете (укажите фактический путь к распакованной папке `open`):

   ```powershell
   docker compose build
   docker compose run --rm -v "C:/путь/к/open:/dataset:ro" --entrypoint python forte-vision scripts/train.py --dataset /dataset
   ```

   При сборке `docker compose run` создаёт каталог `models` в папке проекта. Модель сохраняется в `models/event_detector.joblib`.

4. Запустите сервис:

   ```powershell
   docker compose up -d
   ```

5. Откройте `http://localhost:8000`, введите значение `API_KEY` из `.env` и загрузите `.mov`. Документация API находится на `http://localhost:8000/docs`.

Сервис не загружает модели из интернета при обработке видео. Для развертывания в изолированном контуре заранее перенесите собранный Docker-образ, `models/event_detector.joblib` и (если нужен VLM) веса локальной модели.

## Пример API

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "X-API-Key: $API_KEY" \
  -F "file=@video.mov"
```

Ответ `POST` содержит `job_id`. Опросите его:

```bash
curl http://localhost:8000/api/v1/jobs/JOB_ID -H "X-API-Key: $API_KEY"
```

При завершении JSON содержит `verdict` (`violation` или `no_violation`), массив `violations`, `timecode_sec`, описание, ссылку на открытый нормативный источник и 1 JPEG-кадр в `image_base64`. Для сохранения формата API используются поля из ТЗ. Дополнительные поля `confidence`, `duration_sec` и `rule` раскрывают оценку модели и происхождение правила.

## Локальная VLM (по желанию)

Без Ollama сервис использует нейтральное описание на основе обученного детектора. Чтобы получить краткое описание изображения, установите Ollama отдельно, скачайте мультимодальную модель в локальное хранилище и задайте в `.env` адрес локального сервера (для Ollama на том же компьютере и Docker Desktop — `http://host.docker.internal:11434`) и точное имя модели. Используйте только вариант весов с коммерчески совместимой лицензией: например, карточка [Qwen2.5-VL-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) указывает Apache-2.0, тогда как [Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct/blob/main/LICENSE) содержит лицензию с ограничением на некоммерческое использование. У квантованных сборок проверяйте лицензию конкретных весов отдельно. Разрешены только loopback, `host.docker.internal` и имя контейнера `ollama`; произвольные удалённые адреса отвергаются.

VLM получает только один кадр-кандидат. Он не решает, было ли нарушено правило, и не может читать документы за кадром. Для каждого срабатывания результат остаётся на проверке человека.

## Модель и границы вывода

Обучение строит компактный Extra Trees классификатор по HOG-признакам и простым показателям движения. Положительный класс формируется вокруг метки времени (±2 секунды); фоны берутся дальше 6 секунд от размеченного события и из роликов без нарушения. Разделение для ориентировочной проверки идёт по целым видео, затем финальная модель переобучается на всём открытом наборе. Порог по умолчанию — 45%; настройки и повторное обучение не могут опустить его ниже. Малый набор не даёт надёжной оценки качества.

В таблице есть только метка «нарушение/без нарушения» и временная отметка — названия событий и конкретного нормативного пункта нет. По отмеченным фрагментам оформлено кандидатное правило: направлять на ручную проверку эпизоды, где другой человек подходит к рабочему месту кассира/входит в рабочую зону, либо сотрудник встаёт, отходит или меняется местами с другим человеком. Обычный наклон или жест отдельно нарушением не считается. Это гипотеза по визуальным примерам, а не установленная причина метки и не юридическое правило. Ссылка на нормативный акт дана только для последующей экспертной сверки. Видео не подтверждает допуск к рабочей зоне, проводки, пересчёт, документы, разрешения, подписи или внутренние регламенты. Ложные срабатывания и пропуски возможны; особенно велика неопределённость на другом ракурсе и на новых категориях.

На отложенной выборке исходный порог 4% дал precision около 5% и recall около 41%. На пороге 45% эта выборка не дала срабатываний (precision и recall равны 0): это означает, что строгий фильтр может скрыть и настоящие события, а не то, что зрение улучшилось. Это исследовательский baseline, не готовая для банка модель. API и интерфейс показывают метрики и предупреждают о низком качестве. Для улучшения нужны размеченные типы событий и интервалы, репрезентативные видео, более сильная локальная VLM/видеомодель и калибровка на независимых клипах.

Источник: [Постановление Правления Национального Банка Республики Казахстан от 29 ноября 2019 года № 231](https://adilet.zan.kz/rus/docs/V1900019680). Проверьте действующую редакцию и соответствие каждой категории перед демонстрацией как правового правила.

## Использованные проекты как инженерные ориентиры

В этом проекте использованы общие архитектурные приёмы, а не скопированные исходные файлы:

- [Violation-detector-task](https://github.com/SumitJadhav12/Violation-detector-task) — двухшаговая асинхронная API-схема, очередь задач и доказательные кадры.
- [sweethearting-detection](https://github.com/MuhamedEminKrd/sweethearting-detection) — идея временного подавления повторов и событийного кадра. Его правила рассчитаны на конкретную кассовую сцену и угол камеры, поэтому геометрия позы в этом решении не переносилась.
- [DeepCamera](https://github.com/SharpAI/DeepCamera) — идея запуска визуального языкового анализа локально; здесь VLM-обогащение подключается только через loopback Ollama.

## Перед публичным демо

- Поднимайте порог выше `0.45` только после оценки на отдельной валидации; опускать ниже 45% приложение не позволит.
- Сверьте `model_ready` на `/health`, корректность времён и кадров на всех обучающих видео и время обработки на целевом сервере.
- Проверьте API-ключ с жюри, доступность публичного HTTPS адреса, лимит прокси-загрузки не менее 30 МБ и срок обработки до 5 минут.
- Не публикуйте открытые видео, модель, ключ или кадры. Не добавляйте тестовые видео в обучение.
